# README 专业工程入口页设计

## 背景

现有 README 已覆盖大量 API 和 curl 示例，但首屏缺少面向专业读者的项目定位、架构主线、质量边界和运行入口。文档需要服务于架构评审、后端开发接手和运维交接，而不是承担完整 API 手册的职责。

## 目标

- 用一页文档说明 Suno Mall 的业务闭环、架构形态和模块边界。
- 让新开发者能在几分钟内完成构建、启动和健康检查。
- 明确配置注入、安全基线、测试命令和当前阶段边界。
- 将详细 API、需求流程和运维细节导向已有 `docs/` 文档，避免 README 与实现产生双重维护。

## 非目标

- 不改变 Java 代码、数据库迁移、接口行为或部署配置。
- 不删除已有 API/curl 资料；需要保留的细节应通过文档导航继续可达。
- 不宣称 Phase 0 已完成所有生产安全和业务治理要求。

## 结构设计

README 按以下顺序组织：

1. 项目一句话定位、状态徽章和文档入口。
2. 业务闭环与核心能力。
3. 架构形态、模块边界和关键工程约束。
4. 技术栈与运行前置条件。
5. H2 本地启动、MySQL 验证、质量验证命令。
6. 配置与安全基线、Actuator 探针。
7. 代表性 API 分组和完整接口文档链接。
8. 测试、开发流程、需求流程图和路线边界。
9. 许可与贡献说明（以仓库实际文件为准）。

## 术语和表达

- 中文为主，保留 Spring Boot、Flyway、JWT、RBAC、Profile、Actuator 等工程术语。
- 使用“模块化单体”“应用层/领域层/基础设施边界”“幂等”“审计”“可观测性”等准确术语，避免营销化表述。
- 命令必须使用当前仓库可执行的 Maven Wrapper、脚本和路径。
- 对 demo seed、Mock provider、Docker/Testcontainers 等能力标注适用范围，不与生产能力混淆。

## 验收标准

- README 不再承担完整 curl 手册；完整 API 和流程仍可从 README 导航到。
- 快速启动命令、Profile、密钥变量、健康探针与当前实现一致。
- 模块数量、Java/Spring Boot 版本、验证命令与 `pom.xml` 和现有开发文档一致。
- `./scripts/verify-repository.sh`、`./scripts/verify-docs.sh` 通过。
- Markdown 链接、代码围栏、目录结构和中文排版无明显错误。
